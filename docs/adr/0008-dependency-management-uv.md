# 0008. Adopt uv (Astral) for Dependency Management; Retire Poetry and requirements.txt

Date: 2026-06-26
Status: Accepted

## Context

The backend carried **two competing dependency definitions**:

- `backend/pyproject.toml` in **Poetry** format (`[tool.poetry]`), used as the
  conceptual manifest, and
- `backend/requirements.txt`, a hand-maintained flat list consumed by the
  `Dockerfile` (`pip install -r requirements.txt`) and CI.

This caused concrete problems:

1. **Duplication / drift.** The two files had to be kept in sync by hand. They
   already diverged in version pinning style (Poetry carets vs. bare/`>=` pins),
   and nothing enforced agreement.
2. **No committed lockfile.** Neither a `poetry.lock` nor a pinned `requirements`
   set was under version control, so installs were **not reproducible** — local,
   CI, and Docker could resolve different transitive versions.
3. **Slow installs** in CI and image builds.
4. A latent correctness bug surfaced during the 2026-06-26 broker audit: the RabbitMQ
   integration test was permanently skipped because `testcontainers[rabbitmq]`/`pika`
   was in neither file — i.e. the dependency surface itself was unverified.

We already use **Ruff** (also from Astral) for linting, so adopting `uv` keeps the
toolchain coherent.

## Decision

Standardize on **[uv](https://docs.astral.sh/uv/)** as the single dependency and
environment manager.

- **One manifest, PEP 621.** `backend/pyproject.toml` is rewritten to the standard
  `[project]` table with runtime dependencies, plus a `[dependency-groups] dev`
  group for test/lint/type tooling. No `[tool.poetry]`.
- **Committed lockfile.** `backend/uv.lock` is generated by `uv lock` and committed,
  giving fully reproducible resolution across machines.
- **Pinned interpreter.** `backend/.python-version` pins CPython `3.11` (matching CI
  and the `requires-python = ">=3.11"` constraint); uv downloads/manages it.
- **Build backend.** `hatchling` builds the `src` package and exposes the console
  scripts (`fitsci-evaluate`, `fitsci-worker`).
- **Dockerfile** installs via `uv sync --frozen` in a layered, cache-mounted build
  (deps first, then project), using the official `ghcr.io/astral-sh/uv` image.
- **CI** uses `astral-sh/setup-uv` + `uv sync --frozen` and runs everything through
  `uv run` (`pytest`, `ruff`, `mypy`).
- **`requirements.txt` is deleted**; all references in README and dev scripts move to
  `uv sync` / `uv run`.

## Alternatives considered

- **Keep Poetry.** Rejected: slower resolver/installs, and it still left the
  `requirements.txt` duplication unless we added a `poetry export` step — more
  moving parts, not fewer.
- **Plain pip + requirements.txt (+ pip-tools).** Rejected: no integrated virtualenv
  or Python-version management, weaker reproducibility ergonomics, and it keeps the
  manual-sync burden that caused the drift in the first place.
- **PDM / Hatch environments.** Both are credible PEP 621 managers, but `uv` is
  markedly faster, has become the de-facto Astral standard, and pairs naturally with
  Ruff (already in use), minimizing tool sprawl.

## Consequences

**Positive**
- **Single source of truth** for dependencies; the lockfile makes installs
  reproducible everywhere.
- **Faster** dependency resolution and installs in CI and image builds (Rust-based),
  with effective caching.
- uv **manages the Python toolchain** (fetches 3.11), removing reliance on whatever
  Python happens to be on the host.
- Tooling coherence with Ruff (both Astral).
- The migration was the natural place to add the previously missing
  `testcontainers[postgres,rabbitmq]`, un-skipping the RabbitMQ integration test
  (see the broker audit and ADR-0006).

**Negative / trade-offs**
- Contributors must install `uv` (documented in `README.md` and `scripts/dev.*`).
  Old `pip install -r requirements.txt` instructions no longer apply.
- The lockfile must be regenerated (`uv lock`) and committed when dependencies change.

**Neutral**
- This ADR concerns *tooling*, not runtime architecture; no port/adapter contract
  changes. It supersedes the informal "requirements.txt + Poetry" convention with no
  effect on the hexagonal design ([ADR-0001](./0001-architecture-hexagonal.md)).
